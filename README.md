# VennPlay

*Venn & Play: overlap your Steam libraries, then play.*

Fork of [Timmy1e/what-should-we-play-on-steam](https://gitlab.com/Timmy1e/what-should-we-play-on-steam), originally created by Tim van Leuverden.

Finding a game to play with friends is often tedious: everyone compares their library with the others, by hand. This application compares the Steam libraries of several players to show the games they have in common, using the [Steam APIs](https://developer.valvesoftware.com/wiki/).

## Stack

- Node.js 24 / Express server, which only answers the Steam API routes (`/api/steam/*`).
- Static front end: Vue 2, with EJS views rendered to HTML and SCSS compiled to CSS by `npm run build` ([scripts/build.js](scripts/build.js)), which writes everything into `public/`.
- Hosted on [Vercel](https://vercel.com/): its CDN serves `public/` and caches the Steam API responses for 15 minutes.

## Prerequisites

- [Git](https://git-scm.com/)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (or Docker Engine with the Compose plugin on Linux)
- A Steam API key, generated at [steamcommunity.com/dev/apikey](https://steamcommunity.com/dev/apikey) (requires a Steam account, the requested domain name can be `localhost`)

> Docker is the documented way. Node.js 24 alone also works, see [Without Docker](#without-docker).

## Installation

1. Clone the repository and move into it:

   ```sh
   git clone https://github.com/IamArayel/what-should-we-play-on-steam.git
   cd what-should-we-play-on-steam
   ```

2. Copy `.env.example` to `.env`, then set your Steam API key in it:

   ```env
   STEAM_KEY=YOUR_STEAM_KEY
   ```

   The `.env` file is ignored by Git and Docker: the key never ends up in the repository or in the image.

3. Start Docker Desktop and check that the daemon responds:

   ```sh
   docker info
   ```

   If the command returns a connection error, Docker Desktop is not started yet.

## Run the application locally

From the project root:

```sh
docker compose up --build
```

This command builds the image, builds the static site into `public/`, starts the application, then shows the logs. The server is ready when `Listening on port 3000` appears. `Ctrl+C` stops everything.

The [docker-compose.yml](docker-compose.yml) file runs the application in development mode: the local source code is mounted into the container, so changes are picked up without rebuilding the image.

For later runs, `docker compose up` is enough. After changing the `Dockerfile` or `package.json`, run `docker compose up --build --renew-anon-volumes`: without `--renew-anon-volumes`, the container keeps its previous `node_modules`.

## Use the interface in the browser

1. Open [http://localhost:3000](http://localhost:3000).
2. For each player, enter their Steam custom URL (the part after `steamcommunity.com/id/`) or their 17-digit ID. A new field appears as soon as a name is entered. Once a player is found, typing at least 2 letters of one of their friends' names shows up to 8 suggestions with avatars, friends shared by several entered players first. Friends of players whose friends list is private are not suggested.
3. Click "Roll a game": the application picks a random game among those all players own. Click it again to pick another one.

The "Your libraries" diagram draws one ellipse per player; the highlighted middle, where they all overlap, holds the games the dice picks from. Hovering or focusing an ellipse shows whose library it is.

Steam profiles and game lists must be **public**, otherwise a player's games are not found.

To avoid typing the same players every time, save them as a group:

- **Save**: enter a name under "Groups", then click Save. Saving under an existing name replaces that group.
- **Load**: replaces the current player list with the group's players. Players can then be added or removed for this session only; click Save again to keep the changes.
- **Delete**: the trash button removes the group.

Groups are stored in the browser's `localStorage`, so they are only available in the browser where they were saved.

If port 3000 is already in use, replace `"3000:3000"` with `"8080:3000"` in `docker-compose.yml` and open [http://localhost:8080](http://localhost:8080).

## Work on the code

Depending on the changed file:

| Changed file | To see the change |
| --- | --- |
| `public/scripts/*.js` | Refresh the page |
| `public/styles/*.scss`, `views/*.ejs` | Rebuild the static site (`docker compose exec app npm run build`), then refresh the page |
| `app.js`, `server.js`, `routes/`, `models/` | Restart the application: `docker compose restart app` |
| `package.json`, `Dockerfile` | Rebuild: `docker compose up --build --renew-anon-volumes` |

The files generated by the build (`public/index.html`, `public/404.html`, `public/styles/*.css`, `public/dist/`) are ignored by Git. After a branch switch, rebuild the static site the same way.

## Environment variables

| Variable | Purpose | Default |
| --- | --- | --- |
| `STEAM_KEY` | Steam API key, read from `.env` | none, required |
| `PORT` | Server listening port | `3000` |
| `NODE_ENV` | `production` or `development` | `production` in the image, `development` with Compose |

## Stop and clean up

- Stop: `Ctrl+C` in the `docker compose up` terminal, or `docker compose stop` from another terminal.
- Remove containers and network: `docker compose down`.
- Also remove the built image: `docker compose down --rmi local`.

## Without Docker

With [Node.js 24](https://nodejs.org/), from the project root:

```sh
npm install
npm run build
STEAM_KEY=YOUR_STEAM_KEY npm start
```

On Windows PowerShell, set the key with `$env:STEAM_KEY="YOUR_STEAM_KEY"` before `npm start`.

To run the Docker image as in production (code and static site baked into the image, no mount):

```sh
docker build -t vennplay .
docker run --rm --init -p 3000:3000 -e STEAM_KEY=YOUR_STEAM_KEY vennplay
```

## Deploy to Vercel

The site is deployed on [vennplay.vercel.app](https://vennplay.vercel.app). Vercel detects the Express app (`app.js`), runs `npm run build` (set in [vercel.json](vercel.json)), serves `public/` from its CDN and runs the API as a function. [vercel.json](vercel.json) also holds the security headers, which the Express app reuses so local runs send the same ones.

First setup, once:

1. On [vercel.com/new](https://vercel.com/new), import the GitHub repository.
2. Name the project `vennplay`, which gives the `vennplay.vercel.app` address. Keep the detected settings.
3. Under Environment Variables, add `STEAM_KEY` for the Production and Preview environments.
4. Deploy.

Then every push to `main` deploys to production, and every pull request gets its own preview URL.

## CI/CD

The Docker image is built automatically by GitHub Actions and published to the project's [Container Registry](https://github.com/IamArayel/what-should-we-play-on-steam/pkgs/container/what-should-we-play-on-steam). Production runs on Vercel, see [Deploy to Vercel](#deploy-to-vercel).
